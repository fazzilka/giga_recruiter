# Giga Recruiter

Личный Python-пульт для @Giga_recruiter_bot. Telethon читает только чат целевого
бота и команды владельца в «Избранном». Codex CLI составляет ответы по материалам
кандидата, тексту одной вакансии и истории текущего интервью. Архитектура повторяет разделение слоёв
[oh-my-telegram](https://github.com/yurtsev/oh-my-telegram): runtime, config,
core/di, core/db с repositories и Unit of Work, services и userbot с handlers,
services, texts и utils. Код конкретных функций написан для этого проекта.


## Архитектура

```text
src/
  __main__.py                # запуск python -m src
  config/config.py           # Pydantic, config.toml + совместимый .env
  runtime/
    app.py                   # запуск, подключение, завершение ресурсов
    bootstrap.py             # сигналы и блокировка второго процесса
    containers.py            # сборка Dishka
    interview.py             # планировщик по Telegram-событиям
  core/
    di/providers.py          # зависимости и время жизни HTTP/БД/сервисов
    db/
      db.py                  # SQLAlchemy async engine / session factory
      uow.py                 # транзакция, commit / rollback
      models/workflow.py     # таблицы jobs и interview
      repositories/          # jobs, interviews, workflow
  integrations/codex.py       # subprocess, таймаут, JSON-валидация
  services/
    interview.py             # только жизненный цикл интервью
    queue.py                 # карточки и очередь вакансий
    vacancies.py             # HTML одной страницы, HTTP-кэш
    materials.py             # материалы кандидата и кэш разбора файлов
    prompts.py               # инструкции генерации
  userbot/
    client.py                # создание Telethon-клиента
    handlers/                # регистрация Telegram-событий
    services/commands.py     # разбор /команд и вызов сервисов
    services/telegram.py     # единственная граница Telegram I/O
    texts/commands.py        # справка
    utils/messages.py        # кнопки, ссылки, отпечатки сообщений
```

В отличие от оригинала, пульт остаётся в «Избранном», поэтому слой aiogram-бота,
его клавиатуры и bot token не нужны. SQLite работает без отдельного PostgreSQL,
но разделение SQLAlchemy → repositories → Unit of Work → services сохранено.
Старый app.py — только совместимый запуск в несколько строк, core.py удалён.
Секреты в config.toml не коммить: для образца есть config.example.toml; .env и
переменные окружения имеют приоритет над TOML.

## Быстродействие

- Входящие и изменённые сообщения Telegram будят планировщик сразу. Несколько
  сообщений объединяются за MESSAGE_DEBOUNCE (по умолчанию 0.6 с) вместо старого
  ожидания 3 с плюс интервал опроса 2 с.
- Пока цикл на паузе, запросов опроса нет. При активном ожидании резервная сверка
  выполняется раз в RECONCILIATION_INTERVAL (30 с), чтобы восстановиться после
  потерянного события. Это 2 сверки в минуту вместо 30 в предыдущей версии.
- Неизменённые материалы кандидата разбираются один раз; HTML одной ссылки
  загружается один раз за запуск. Один AsyncClient переиспользует HTTP-соединения.
  /scan загружает до трёх страниц параллельно, сохраняя порядок очереди; уже
  полученные Telegram-карточки повторно не запрашиваются.
- Повторное добавление той же карточки проверяется до Telegram/HTTP запросов.
- Ответы одному рекрутеру остаются последовательными. Скорость самой модели
  зависит от Codex, сети и лимитов подписки; ускорение всего интервью не измерено.

## Подключение

```bash
cd giga-recruiter
cp .env.example .env
uv sync
codex login
codex login status
uv run python -m src doctor
uv run python -m src login
uv run python -m src run
```

Нужен Python >=3.11, uv и установленный Codex CLI. Команды рассчитаны на macOS/Linux.
Вход `codex login` выполняется через ChatGPT: отдельный ключ OpenAI API не нужен,
использование учитывается в доступных лимитах плана. Программа запускает Codex
с сохранённой авторизацией, но без пользовательского config.toml; если модель
не доступна по умолчанию, укажи доступную модель в CODEX_MODEL. Для постоянного
сервиса с API-ключом используется отдельная оплата OpenAI Platform.

Telegram:
1. Открой https://my.telegram.org и войди в свой аккаунт.
2. В API development tools создай приложение (например, название Recruiter,
   short name recruiter_personal, platform Desktop).
3. Запиши api_id и api_hash в локальный .env как TELEGRAM_API_ID и TELEGRAM_API_HASH.
4. При `python -m src login` введи телефон, код и, если нужен, пароль 2FA в терминале.
   Не отправляй код, пароль, api_hash или файл сессии в переписку.

BotFather и дополнительный bot token не нужны. Пока нет авторизации,
программа не читает Telegram и не пишет рекрутеру.

## Материалы

Положи в materials/ резюме и подробное описание своего реального опыта:
resume.pdf/docx/txt/md и experience.md/txt/docx. PDF должен содержать текст,
сканы без OCR не поддерживаются. Перед каждым ответом проверяются имя, размер и
время изменения файлов. Неизменённые PDF/DOCX повторно не разбираются. Изменение
или удаление файла обновляет кэш; чтение вынесено в рабочий поток.
Отдельным файлом можно указать зарплату, формат работы, доступность и стиль ответа.
Уточни, какие части рассказа — реальный опыт, а какие — учебные примеры.
Модель получает все поддерживаемые файлы в этой папке (максимум 100 000 символов),
поэтому не храни там ничего постороннего. Материалы передаются OpenAI.

## Работа

После запуска пиши команды **своему аккаунту в «Избранное»**, не рекрутеру.

- `/help` — полный список команд.
- `/profile` — проверить, прочитались ли материалы.
- `/scan` — последние 30 сообщений только @Giga_recruiter_bot, ID карточек,
  кнопки и разрешённые ссылки. Однозначные карточки, в том числе
  нумерованные списки с несколькими вакансиями, добавляются в очередь: текст
  ссылки должен совпадать с названием кнопки без номера. Кнопка «Далее» не нажимается. Другие сайты не обходятся.
- `/add 123 "Data Analyst" https://rabota.sber.ru/…` — явное сопоставление.
- `/addtext 123 "Data Analyst" "Полный текст вакансии…"` — если страница загружается
  JavaScript или её HTML пока не поддержан.
- `/queue` — только ожидающие и активные вакансии; `/history` — завершённые и пропущенные.
- `/skip` — убрать текущее интервью из очереди и поставить цикл на паузу.
  История сохраняется со статусом `skipped`; `/scan` не добавит эту вакансию повторно.
  Затем `/run` запускает следующую вакансию. Команда ничего не отправляет рекрутеру.
- `/mode auto`, затем `/run` — последовательно нажимать сохранённые кнопки,
  получать вопросы, генерировать и отправлять ответы, переходить к следующей вакансии.
- По умолчанию `/mode draft`: каждый ответ показывается в Избранном;
  `/send` отправляет и продолжает цикл, `/answer ваш текст` отправляет свой ответ.
- `/pause`, `/resume`, `/status`, `/draft`, `/retry` — управление.

Все аргументы с пробелами заключай в двойные кавычки. В /answer можно писать обычный
текст, свободный текст после /answer передаётся целиком, включая любые кавычки.
Остальные команды разбираются через shlex.
Разрешённые хосты вакансий перечислены в VACANCY_HOSTS через запятую; начальный
хост — rabota.sber.ru. Разрешено до пяти перенаправлений, с проверкой HTTPS и разрешённого домена на каждом шаге. Парсер извлекает блок вакансии Сбера (либо main/article для других страниц)
без меню, скриптов и футера, не скачивает изображения и вложения.
HTML конкретной страницы ещё нужно проверить на реальной ссылке.

Резюме, база состояния и Telegram-сессия исключены из Git.
Состояние хранится в SQLite: state/recruiter.sqlite3. При первом запуске старая
state/queue.json импортируется одной транзакцией, исходный файл остаётся на месте. Сессия в state/telegram.session
даёт доступ к аккаунту, держи её локально; очередь содержит приватную переписку.
Программа не сохраняет отдельные сессии Codex (--ephemeral) и не выводит его логи.
Только один экземпляр может работать с этой папкой состояния.

## Восстановление и ограничения первой версии

После перезапуска всегда пауза и режим draft. `/resume` продолжает сохранённое
интервью; уже обработанные вопросы не отвечаются повторно. MAX_ANSWERS ограничивает
число ответов на одно интервью. Изменившийся вопрос инвалидирует старый ответ.
Неизвестные факты, противоречия в материалах и технические тесты останавливают цикл:
ответь через `/answer`, затем `/resume`. Определение конца интервью выполняет модель;
это нужно проверить на примерах реальной переписки.

Кнопки внутри интервью пока требуют ручного выбора в чате рекрутера.
Уведомление покажет `/handled ID` — выполни после выбора, затем `/resume`.
Телефон, геолокация и Web App кнопки автоматически не нажимаются.

При сетевой ошибке отправка/нажатие могут иметь неопределённый результат. Автоматически
они НЕ повторяются. Проверь чат и восстанови состояние:
- `/recover sent` — отправляемый ответ действительно дошёл;
- `/recover not-sent` — ответ точно не дошёл; `/send` повторяет отправку;
- `/recover clicked` — интервью после нажатия уже началось (при необходимости
  начни его вручную); затем `/resume`.

При FloodWait цикл останавливается на указанное Telegram время. Если бот не присылает
вопрос, программа ждёт и не отправляет напоминания. Если список карточек устарел,
нажатие не выполняется. Модель не получает доступ к Telegram: все отправки делает
Python-код только в TARGET_BOT. Вакансии/сообщения передаются модели как недоверенные
данные; CLI работает в read-only sandbox с отключённым shell tool.

Для завершения адаптации нужны реальные ссылки вакансий, снимок/текст карточки с
кнопками и пример интервью. До этого обещать полную совместимость с конкретным
ботом нельзя. Боевой тест не проводился: Telegram ещё не авторизован.

## Метрики и диагностика сбоев

Диагностика находится в `src/core/telemetry.py` и подключается через DI.
Работает локально: внешние сервисы мониторинга и отдельный сервер не нужны.

- `/metrics` в «Избранном» — число вызовов, успешных операций, сбоев и отмен,
  средняя и максимальная задержка Codex, Telegram, загрузки вакансий и команд.
  Счётчики сохраняются между перезапусками.
- При ошибке автоматически сохраняется `state/diagnostics/report.json`;
  сообщение об остановке содержит ID ошибки. `/diagnostics` обновляет отчёт
  и показывает путь. Приложи этот JSON к нашему чату для разбора сбоя.
- Если программа уже остановилась: `uv run python -m src diagnostics`.
  Авторизация Telegram и запуск интервью для этой команды не требуются.

Отчёт содержит время, тип ошибки, ID запуска/ошибки, фазу интервью, цепочку типов
исключений и стек (имена файлов, функции, строки), счётчики, задержки, версию
Python и ОС. Для Codex сохраняется фиксированная категория: auth, rate_limit,
access, network, timeout, invalid_response или unknown. Категория CLI определяется
по его временному stderr и является подсказкой, а не гарантированным диагнозом.

Ключи, сессии, телефон, резюме, вакансии, аргументы команд и переписка в отчёт
не включаются. Тексты исключений и локальные переменные не записываются.
Сырой stderr Codex удаляется вместе с временной папкой после вызова.
`events.jsonl` ротируется: текущий файл до 1 МБ и три резервных; в отчёте —
до 100 последних ошибок. Отчёт и метрики записываются атомарно. Если запись
метрик не удалась, исходное исключение сохраняется, а `/metrics` покажет проблему.

Обычная остановка/отмена отделена от ошибок. Падение питания, SIGKILL или заполненный
диск могут помешать записи последнего события; ранее сохранённые метрики остаются.
Программа не отправляет отчёт другим людям автоматически.


## Терминальные логи и пауза перед ответом

При `uv run python -m src run` в терминале видны этапы обработки, команды без
аргументов, HTTP-статусы и шаги перенаправлений, время выполнения операций,
решение модели (reply/wait/done/needs_input), ожидание отправки и её результат.
Ошибки содержат ID инцидента и стек (файл, строка, функция); HTTP-статус попадает
также в отчёт `/diagnostics`. Секреты и тексты сообщений в логи не выводятся.

По умолчанию после подготовки ответа программа ждёт 30 секунд перед отправкой.
Это дополнительная пауза, не включая время генерации. Настройка в `.env`:

```dotenv
SEND_DELAY_SECONDS=30
```

Или `send_delay = 30` в секции `[interview]` файла config.toml. Значение 0 отключает
паузу. Переменная `.env` имеет приоритет. После изменения нужен перезапуск.
Пауза применяется также к `/send` и `/answer`. Команда `/pause` прерывает ожидание,
сохраняя черновик; после этого `/send` запускает новую паузу. Во время ожидания
состояние ещё `interview`, а не `sending`: перезапуск не считается неопределённой
отправкой. После ожидания вопрос повторно проверяется; устаревший ответ не уходит.

Ответы модели ориентированы на короткую связную переписку без декоративного
оформления. Длинное и среднее тире в сгенерированном ответе заменяются на дефис;
ответы, введённые пользователем вручную, не переписываются.


## Завершение интервью и оценка рекрутера

Явное сообщение «Спасибо за интервью» или «Интервью завершено» обрабатывается
до проверки кнопок. Вакансия получает статус done и исчезает из `/queue`, оставаясь
в `/history` вместе с сохранённым диалогом. Обычное «спасибо» не завершает интервью.
Одного `done` от модели недостаточно: вопрос «Остались ли у Вас вопросы?» требует
ответа кандидата, а не переноса вакансии в историю. Неподтверждённое завершение
блокируется и отражается в терминале.
После финального текста есть короткое ожидание следующего сообщения с оценкой
(`feedback_wait = 2` в `[interview]`). Шкала со звёздами и просьбой оценить работу
рекрутера автоматически получает 5 звёзд, согласно настройке пользователя в чате.
Кнопки следующих вакансий не мешают распознаванию завершения.
Если рекрутер повторно спрашивает о дополнительных вопросах после ответа на вопросы
кандидата, цикл отвечает «Пока других вопросов нет, спасибо.», чтобы не повторять
одни и те же уточнения бесконечно. В режиме auto такой ответ отправляется уже
на первое приглашение: программа не инициирует необязательные встречные вопросы.
В режиме draft первое приглашение позволяет подготовить вопрос для проверки.

Намерение нажать оценку сохраняется до запроса. При сетевом сбое или таймауте
повторного автоматического нажатия нет. Если callback вернул таймаут, программа
перечитывает ту же карточку: текст «Спасибо за обратную связь!» без кнопок
подтверждает принятую оценку. Без этого подтверждения проверь чат и используй `/recover rated`,
если оценка уже отправлена, или `/recover not-rated`, если точно не отправлена;
затем `/resume`. Другие неизвестные кнопки по-прежнему требуют ручного выбора.

`/scan` сопоставляет ссылки и кнопки списка по названию, а не их позиции. Неясные
и неоднозначные соответствия не выбираются. Обработанная вакансия не добавляется
повторно по ссылке с тем же числовым ID, даже если изменились номер кнопки или
сообщение меню. Сканируется текущая доступная история из 30 сообщений; переход
по страницам выполняется командой `/next`, затем `/scan`. Постоянное пополнение
без `/scan` пока не реализовано. Повторный `/next` ждёт обновления меню;
во время активного интервью переход заблокирован.

## Продолжение после перезапуска и needs_input

После запуска режим всегда draft и цикл на паузе. Для автоматической работы
сначала `/mode auto`, затем `/run` (или `/resume`). Эти команды продолжают работу
с новыми вопросами, но не пересоздают ответ на вопрос, ранее отмеченный needs_input.

Если модель запросила уточнение, а ты добавил сведения в materials/ или обновил
промпт, используй `/retry`. Команда возвращает последний неотвеченный блок сообщений
рекрутера на генерацию, сохраняя предыдущие ответы. Поддерживается восстановление
старого состояния, где needs_input ошибочно считался полностью обработанным вопросом.
Без `/mode auto` результат будет черновиком: `/draft`, затем `/send`.

`/retry` не сбрасывает интервью и не повторяет уже отправленные ответы. Если в Telegram
после выбранного вопроса уже есть исходящее сообщение, повтор блокируется для проверки
чата. При неопределённой отправке сначала используется соответствующий `/recover`.
Для неуказанных в резюме и описании опыта технических навыков действует правило
кандидата: «знаком на уровне теории, на практике не работал». Такие вопросы не
требуют needs_input. Явно указанные сведения имеют приоритет; практические кейсы,
стаж и метрики не придумываются. Неизвестные личные условия и согласия по-прежнему
нужно уточнять, они не заменяются ответом про теоретическое знакомство.

## Обновлённые сообщения со списком вакансий

После завершения интервью Сбер может менять список, нумерацию и callback-кнопки.
Перед запуском ожидающей вакансии программа проверяет сохранённую карточку.
Если существует более новое меню вакансий, выбирается кнопка только из него:
неизменившаяся историческая карточка не подтверждает актуальность callback.
Если её отпечаток изменился, карточка повторно сопоставляется с ID вакансии из
ссылки. Если исходное сообщение больше не подходит, проверяются последние
30 сообщений рекрутера. При однозначном совпадении ссылка на карточку обновляется;
сохранённый текст вакансии, порядок очереди, история и ключ записи не меняются.
Без ссылки либо без точного совпадения автоматического нажатия нет.
Если карточка первой вакансии недоступна, цикл ищет следующую доступную вакансию
в очереди. Недоступные записи сохраняют статус `queued`, порядок и историю;
при следующем `/run` они снова проверяются. Сетевые ошибки не считаются отсутствием
карточки. В режиме auto при отсутствии актуального меню отправляется
`/change_vacancy`, затем программа ждёт обновления и перелистывает «Далее», пока
не найдёт ожидающую вакансию. Неизменившееся меню не нажимается повторно;
повтор страницы, конец списка или 20 просмотренных страниц завершают поиск.
Если доступных карточек нет совсем, цикл ставится на паузу с уведомлением;
очередь не считается завершённой. Открой нужную страницу списка, затем `/scan` и `/run`.

`/scan` также обновляет привязку уже ожидающих вакансий к свежему меню, без повторной
загрузки текста страницы. Завершённые вакансии не возвращаются в очередь.
Если подходящего меню нет в последних сообщениях, открой список вакансий в чате
рекрутера, затем выполни `/scan`, `/mode auto` и `/run` в «Избранном».

Если после старого нажатия диалог так и не начался, проверь чат и используй
`/recover not-started`: вакансия вернётся в очередь, если история и счётчик ответов
ещё пусты. Завершённые или начавшиеся интервью эта команда не сбрасывает.

Для исправления старого ложного завершения на вопросе «Остались ли у Вас вопросы?»
используй `/recover unfinished URL`. Активного интервью при этом быть не должно.
Команда проверяет отсутствие финального сообщения и оценки, сверяет последний
вопрос с Telegram и блокирует восстановление, если на него уже есть исходящий ответ.
После восстановления `/resume` продолжает сохранённый диалог.

Ожидание новых сообщений ограничено `RECRUITER_RESPONSE_TIMEOUT` (по умолчанию
180 секунд). Если диалог ещё не начался, при превышении цикл останавливается с
кодом `recruiter_timeout`, сообщением в пульте и записью в диагностике. Если ответы
уже отправлялись, задержка рекрутера вызывает одно уведомление и предупреждение
в терминале, но цикл остаётся включённым и обрабатывает позднее сообщение.
`/resume` начинает новый период ожидания без повторной отправки ответа или клика.
